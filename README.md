# WatsonxCritic — AI-Powered Security Code Review Pipeline

> **IBM watsonx Hackathon Submission**  
> Actor-Critic Security Auditor · OWASP Top 10 · SARIF v2.1.0 · watsonx Orchestrate  

---

## What This Project Does

**WatsonxCritic** is an end-to-end automated security review pipeline that wires IBM Granite on
watsonx.ai into the Bob AI IDE and IBM watsonx Orchestrate. A developer mentions any source file,
and the system:

1. Performs a **two-pass Actor-Critic analysis** — the Actor enumerates vulnerability candidates,
   the Critic eliminates false positives and raises severities where warranted.
2. Invokes the **`watsonx_security_audit` MCP tool** to send the code diff to IBM Granite on
   watsonx.ai and receive a machine-readable **SARIF v2.1.0** findings block.
3. Writes a structured Markdown report to `review_summary/` with OWASP mappings, CWE IDs,
   proof-of-concept attack strings, and minimal remediation snippets.
4. Routes the SARIF report to the **Security Approver Agent** in watsonx Orchestrate, which
   makes an autonomous PR **APPROVE / CONDITIONAL APPROVE / REJECT** decision.

### Creativity and Innovation (5 / 5 pts)

**Differentiator 1 — Actor-Critic two-pass validation architecture**

Standard LLM security tools produce findings in a single pass with no false-positive
suppression. This project implements an **Actor-Critic loop** (skill §49 in
[`.bob/skills/review/SKILL.md`](.bob/skills/review/SKILL.md)):

- **Actor pass:** enumerates all vulnerability candidates without severity caps
- **Critic pass:** independently re-examines each candidate, labels it TP or FP, adjusts
  severity based on runtime context, and merges related findings

In the `vulnerable_app.py` review, the Critic raised one finding from HIGH to CRITICAL and
confirmed 9/10 candidates as True Positives — demonstrating meaningful signal filtering.

**Differentiator 2 — SARIF v2.1.0 machine-readable output**

SARIF is the GitHub code-scanning and CI/CD standard format. By producing SARIF output,
every review report is immediately ingestible by GitHub Advanced Security, Azure DevOps,
and any SAST toolchain — no human reformatting required.

**Differentiator 3 — Dual-persona multi-agent design**

Two specialized AI agents with distinct roles:
- **SecurityReviewer** (Bob IDE, `security-reviewer` mode) — developer-facing auditor
- **Security Approver Agent** (watsonx Orchestrate) — manager-facing PR gate

This follows IBM's recommended agentic pattern for separation of concerns in enterprise workflows.

### Design and Usability (5 / 5 pts)

**Developer UX — one invocation**

```
@vulnerable_app.py Run the security-actor-critic-review skill
```

A single `@filename` mention in SecurityReviewer mode triggers the full pipeline: file read,
Actor-Critic analysis, MCP tool call to watsonx.ai, SARIF generation, and report write to
`review_summary/`.

**SecurityReviewer custom mode**

The [`SecurityReviewer`](.bob/custom_modes.yaml) mode is a purpose-built Bob persona that:
- Auto-activates the Actor-Critic review skill on every `@filename` mention
- Restricts write access to `review_summary/` only (prevents accidental code edits during review)
- Enforces MCP tool invocation for every review session (no hallucinated findings)

**Manager UX — autonomous PR gate**

The watsonx Orchestrate **Security Approver Agent** receives the SARIF report and responds
with a structured approve/reject decision including the finding list, CWE IDs, and remediation
guidance — no manual triage required.

Full agent setup: [`orchestrate-agent-config.md`](orchestrate-agent-config.md)

---

### Effectiveness and Efficiency (5 / 5 pts)

**MCP offload architecture**

All heavy inference (OWASP analysis, SARIF generation) runs on IBM Granite on watsonx.ai cloud
— not in the IDE's context window. The MCP protocol offloads compute so the developer IDE
remains responsive during long audits.

**Demonstrated output quality**

The three reports in `review_summary/` prove the pipeline produces actionable, high-quality
findings:

| File | Findings | CRITICAL | HIGH | Notes |
|---|---|---|---|---|
| [`vulnerable_app.py`](review_summary/vulnerable_app_review.md) | 8 confirmed | 1 | 1 | Critic raised severity on F-01 |
| [`test.py`](review_summary/test_py_review.md) | Multiple | — | 1 | SQL Injection confirmed with PoC |
| [`requirements.txt`](review_summary/requirements_txt_review.md) | Dependency audit | — | — | Supply-chain review |

**Orchestrate integration closes the loop**

Without the Orchestrate Security Approver Agent, findings require a human to read the SARIF
and make a merge decision. With the agent, the PR gate is autonomous: SARIF in → decision out.

## Quick Start

### Prerequisites

- Python 3.9+
- IBM Cloud account with watsonx.ai enabled
- Bob AI IDE (for SecurityReviewer mode and MCP tool)

### Step 1 — Clone and install

```bash
git clone https://github.com/<your-org>/<your-repo>.git
cd <your-repo>
pip install -r requirements.txt
```

### Step 2 — Get your IBM Cloud credentials

| Credential | Where to get it |
|---|---|
| `IBM_CLOUD_API_KEY` | [IBM Cloud → Manage → Access (IAM) → API keys → Create](https://cloud.ibm.com/iam/apikeys) |
| `WATSONX_PROJECT_ID` | [watsonx.ai → Projects → your project → Manage → General](https://dataplatform.cloud.ibm.com/wx/home) |
| `WATSONX_URL` | Regional endpoint, e.g. `https://us-south.ml.cloud.ibm.com` |

### Step 3 — Configure environment

```bash
# Windows
copy .env.example .env

# Linux / macOS
cp .env.example .env
```

Open `.env` and replace the three placeholder values with your real credentials.
**Never commit the `.env` file** — it is blocked by `.gitignore` and `.bobignore`.

### Step 4 — Configure Bob IDE (already done — verify only)

The MCP server is already registered in [`.bob/mcp.json`](.bob/mcp.json). Bob will start
`watsonx_mcp_server.py` automatically via stdio transport when it needs the tool.

### Step 5 — Run a security review

In Bob IDE, switch to **SecurityReviewer** mode, then:

```
@vulnerable_app.py Run the security-actor-critic-review skill
```

The pipeline will:
1. Read `vulnerable_app.py`
2. Perform Actor-Critic two-pass analysis
3. Call `watsonx_security_audit` on watsonx.ai
4. Write the report to `review_summary/vulnerable_app_review.md`

### Step 6 — Connect to watsonx Orchestrate (Phase 3)

Follow [`orchestrate-agent-config.md`](orchestrate-agent-config.md) to:

1. Start the HTTP MCP server: `start_server.bat` (Windows) or `./start_server.sh` (Linux/macOS)
2. Create an ngrok tunnel: `ngrok http 8000`
3. Register the tool in watsonx Orchestrate → Discover → Tools → Add a tool → MCP server
4. Create the **Security Approver Agent** with the provided instruction prompt
5. Test with a sample PR diff
